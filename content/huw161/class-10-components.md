### Lecture: components

Every element on a page has a job.

| Job          | Components                         | Ask                                 |
| ------------ | ---------------------------------- | ----------------------------------- |
| **Tell**     | Headings, paragraphs, labels       | What does this tell me?             |
| **Show**     | Images, icons, video               | What does this help me understand?  |
| **Do**       | Buttons, links, inputs, toggles    | What happens if I touch this?       |
| **Organize** | Nav, cards, lists, sections, footer | What belongs together?              |

**Affordance**
- How a thing tells you what it does
- Buttons look pressable, links look clickable
- Broken when a component lies about its job (fake button, gray text that's a link)

**Names the web uses**
- `h1` heading, `p` paragraph, `img` image, `button`, `a` link, `nav`, `ul` list
- Heading sizes show importance: big, medium, small
- One main button per screen

**Try it**
- Open any site your partner might use
- Label 5 elements: tell, show, do, or organize?

**In a wireframe**
- Image: gray box with an X
- Text: lines
- Button: labeled rectangle
- Pick 5–6 components your partner's page needs

### Demo: auto layout + components

- **Button**
	- Type text, **Shift+A** (auto layout)
	- Add padding + fill
	- Change the text: the button grows
- **Component**
	- Select button, **Cmd+Opt+K** (Ctrl+Alt+K on Windows)
	- Drag out 3 copies, change one label
	- Edit the main component: all copies update
- **Card**
	- Image box + heading + text + button
	- Select all, **Shift+A**: vertical, set gap + padding
	- Make it a component
	- Duplicate 3×, select, **Shift+A**: a row of cards
